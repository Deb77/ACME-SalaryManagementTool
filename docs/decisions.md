# Decision log

The choices made while planning and building, newest last. Bigger technical decisions have their own ADR in [`adr/`](adr/); this page is the index and also records the smaller calls that don't need one.

| # | Date | Decision | Alternatives considered | Why |

| 2 | 2026-11-18 | Drop the first design draft (SQLite, single HR Manager, no sign-in) | Keep it alongside the requirements | It contradicted the current scope (Postgres with RLS, two roles, import, Ask AI). Replaced by [api.md](api.md), [auth.md](auth.md) and [ui.md](ui.md). |

| 5 | 2026-11-18 | npm workspaces monorepo: `apps/web`, `apps/api`, `packages/shared` | Single package; separate repos; Turborepo/Nx | Shared Zod schemas catch API/UI drift at compile time; one install, one CI. Plain workspaces are enough at this size. |

| 10 | 2026-11-18 | Sessions in Postgres with hand-rolled cookie auth; three database roles so the app cannot bypass RLS | JWT; Better Auth; Clerk/Auth0; Passport | Simplest secure option a reviewer can read in one sitting; role/country changes apply on the next request. | 15 | 2026-11-18 | Design the API, auth layer and UI library with three parallel AI subagents, then reconcile | One sequential AI session | Independent areas with separate files; reconciling afterwards caught naming mismatches (`audit_events`, `app.user_role`). |

| 18 | 2026-11-18 | Organise components by atomic design (atoms, molecules, organisms, templates), with an ESLint rule that blocks imports from a higher level | Flat `components/` folder; group by feature | The level shows how big and reusable a component is, and the lint rule keeps the dependency direction one way. Ladle groups stories by the same levels. |
| 19 | 2026-11-20 | Replace Ant Design with Mantine 9, styled only through CSS modules; supersedes #11 | Keep antd (theme tokens for antd, CSS modules for our markup); shadcn/ui + Tailwind; MUI; Chakra | antd needed two styling mechanisms and lost specificity fights with our CSS (the broken dialogs). | 20 | 2026-11-20 | Plain markup for StatusTag, FormField, FileDropzone, avatars and the empty/error states; Tabler icons | Mantine Badge, Input.Wrapper, `@mantine/dropzone`, Avatar; keep `@ant-design/icons` | These are layout and colour only, so a library adds props and markup without behaviour. Tabler is the icon set Mantine recommends. |
| 21 | 2026-11-20 | Add Mantine's official docs MCP server (`@mantine/mcp-server`, pinned to 9.8.0) in a project `.mcp.json` | Paste `mantine.dev/llms.txt` into prompts; rely on the model's memory | The AI assistant looks up current v9 props and Styles API instead of guessing, and the pin keeps the docs on the same version as `@mantine/core`. |
| 22 | 2026-11-20 | `packages/shared` is grouped by domain (`core/`, `health/`, `employee/`, `salary-change/`, `ai/`) with `<domain>.schema.ts` files, a co-located test each and one barrel; a lint rule stops it importing from the apps; a `development` export condition points the API dev server at `src/` | A flat `src/`; subpath exports per domain; a separate contracts package | Matches common monorepo practice for shared Zod contracts while staying small. One barrel keeps imports as `@acme/shared`. Without the condition, `tsx` read stale `dist/` and schema edits did not reach the API until a rebuild. |
| 23 | 2026-11-20 | RBAC with roles in the database: `roles`, `permissions` and `role_permissions` tables, one role per user, each role a permission set plus a country scope (`all` or `assigned`). The auth layer checks `requirePermission` on every route. Global HR and Country HR are seeded system roles; the permission catalogue is defined in code | A fixed role enum checked with `requireRole`; a role-to-permission map in code | Global HR can add a role (for example a read-only finance viewer) without a deploy. Routes name permissions, so the catalogue stays in code. RLS reads only the resolved countries, never a role name, which also removes the `OR` that stopped indexes being used. Escalation rules are in [auth.md](auth.md#roles-and-permissions-rbac). |
| 24 | 2026-11-20 | Country HR imports only their assigned countries. Rows for other countries are row errors that tell them to ask Global HR, and are never applied | Reject the whole file; silently skip the rows | The rest of the file still imports and every row is explained, while changes to other countries stay with Global HR. |
| 25 | 2026-11-20 | Invite links are copied by hand in v1 (shown once to the inviting user); no email | Send invites by email | Email needs a provider and domain setup, and with about 20 users copying a link is workable. |
| 26 | 2026-11-20 | Money is formatted in the currency's own locale (₹32,40,000 for INR), not the viewer's | Format in the viewer's browser locale | Matches how each country's HR team reads its own numbers, and the same amount looks the same for everyone. |
| 30 | 2026-11-20 | Drizzle ORM (`drizzle-orm` 0.45, `drizzle-kit` 0.31) for the schema, migrations and queries; supersedes the Kysely part of #7. The schema is TypeScript in `apps/api/src/db/schema`; `drizzle-kit generate` writes SQL migrations to `apps/api/drizzle`, and the app applies them itself (`npm run db:migrate`). Data, extensions, helper functions and the one `INCLUDE` index are hand-written SQL migrations. The 10,000-employee seed is a deterministic generator (`npm run db:seed`) | Keep Kysely; Prisma | An ORM with typed models and generated migrations, while staying close to SQL. Drizzle can express what database.md needs (checks, partial indexes, composite foreign keys, RLS policies) where Prisma's schema cannot, and RLS scoping is a plain `set_config` in a transaction. |
| 31 | 2026-11-20 | Inversion of control in the API with a small typed container (`apps/api/src/lib/container.ts`, about 60 lines) and one composition root (`apps/api/src/container.ts`). Services and repositories are classes that take their collaborators in the constructor; routes are factories that receive the services they call | awilix, tsyringe or InversifyJS; module-level singletons imported directly | Constructor injection keeps every dependency visible and lets tests swap one entry (a fixed clock, a quiet logger) without mocking modules. A typed registry gives compile-time checks without decorators or `reflect-metadata`; the container is small enough to read in one sitting. |
| 32 | 2026-11-20 | The API connects with `DATABASE_URL` and runs every connection as `acme_app` (`-c role=acme_app` at connect). Migration `0005` creates `acme_app` as `NOLOGIN NOBYPASSRLS`, grants it to the migrator, and adds the grants and RLS policies. Policies are not `FORCE`d | A separate `acme_app` login with its own password (auth.md); `SET ROLE` per transaction | Same protection (the API never runs as the table owner, so RLS always applies and DDL is impossible) without a second password to manage on Render's single-user plan. A deployment can still `ALTER ROLE acme_app LOGIN PASSWORD …` and point `DATABASE_URL` at it. Without `FORCE`, the owner (migrations, seed) bypasses RLS, so the seed needs no scope. |
| 33 | 2026-11-20 | RLS details beyond auth.md: `salary_changes` is filtered by its own copied `country_code` (no join); audit events are visible when in scope, when you are the actor, or (for all-country roles) when they have no country (user and role admin); imports are visible to their uploader or when every touched country is in scope, and only the uploader can change one. Generated employee codes and import undo's deletes run in two small `SECURITY DEFINER` functions | Policies exactly as sketched in auth.md | The copied country (decision #27) keeps the salary policy an index condition. Admin audit rows have no country, so without the extra clause Global HR could not see "who invited whom". Code generation must see every country's codes, which RLS would hide. |
| 34 | 2026-11-20 | Sign-in and invite screens in the web app (`/sign-in`, `/accept-invite#token=…`); the invite token travels in the URL fragment. New contracts: `signInRequestSchema`, `acceptInviteRequestSchema`, `inviteInfoSchema` and query schemas for audit, insights and import rows | Token in the query string | A fragment is never sent to the server, so the token cannot leak through access logs or the Referer header. |
| 35 | 2026-11-20 | Changes from the end-to-end review (browser at six viewports, every endpoint timed and checked against the Zod schemas, `EXPLAIN` as `acme_app`): sign-in limits count only failures, per IP and email (10) plus per IP (50); hire and termination dates cannot be in the future, and leavers are read-only; salaries are capped at 1,000,000,000 major units (`MAX_SALARY_MINOR`) so payroll sums stay exact; unknown filter values return 400; the list counts in a separate query; new indexes `employees_name` and `audit_events_actor_occurred`; no trigram index | Keep a per-IP limit on every attempt; a window `count(*) over ()`; the E2 trigram index | A per-IP limit on all attempts locked a whole office out after ten sign-ins. Future-dated hires and leavers broke the "current salary and status are plain columns" rule. The window count made every page sort all rows in scope (11 ms → 0.5 ms for the first page). ILIKE is not leakproof, so a trigram index cannot be used under RLS, and search measured 3.5 ms without one. |

## Open questions

Raised by the design docs and not decided yet:

- Can Render's default Postgres user create the `acme_app` role (migration 0005)? If not, create it once from Render's shell as an admin and re-run the migration.
- Where the demo password lives (README or submission note only).
- Future-dated salary changes, moving an employee to another country, and reinstating a terminated employee (all rejected in v1).
- Import: a time limit on undo.
